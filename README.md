# Traceback: A Privacy-First Lost & Found Platform

Traceback is a modern, reliable, and privacy-conscious web application designed to help people reconnect with their lost belongings. Built with a powerful tech stack including Next.js, Firebase, and Google's Genkit, it offers a seamless experience for both reporting lost items and helping honest finders return them.

## ✨ Core Features

*   **👥 Dual Report Forms**: Separate, intuitive forms for reporting **Lost Items** and **Found Items**.
*   **🤖 AI-Powered Matching**: Leverages AI to compare descriptions and (optional) images, calculating a match probability to connect the right people.
*   **🔒 Secure & Private Handover**: A robust, privacy-first claim and verification process.
    *   **AI-Generated Questions**: AI generates non-invasive, externally-verifiable questions to help owners prove ownership.
    *   **Secure PIN System**: A one-time PIN is generated by the item owner and verified by the finder to confirm the handover securely, without prematurely exposing contact details.
    *   **Contact Exchange**: After a claim is approved, contact details are shared privately between only the two parties involved.
*   **👤 User Dashboard**: A centralized place for users to manage their reported items, view potential matches, and track the status of their claims.
*   **🔥 Real-time & Scalable**: Built on Firebase (Firestore and Auth) for a real-time, secure, and scalable backend.
*   **💅 Sleek & Responsive UI**: A modern interface built with ShadCN UI and Tailwind CSS, providing a great experience on any device.

## 🚀 Tech Stack

*   **Framework**: [Next.js](https://nextjs.org/) (App Router)
*   **Backend & Database**: [Firebase](https://firebase.google.com/) (Firestore, Authentication, Storage)

*   **Styling**: [Tailwind CSS](https://tailwindcss.com/), [ShadCN UI](https://ui.shadcn.com/)

## ⚙️ Getting Started

### 1. Prerequisites

*   Node.js (v18 or later)
*   A Firebase project.

### 2. Setup

1.  **Clone the repository:**
    ```bash
    git clone <your-repo-url>
    cd <repo-name>
    ```

2.  **Install dependencies:**
    ```bash
    npm install
    ```

3.  **Configure Environment Variables:**

    Create a `.env` file in the root of the project and add your Firebase project configuration. You can get these from your Firebase project settings.

    ```env
    NEXT_PUBLIC_FIREBASE_API_KEY=AIza...
    NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your-project-id.firebaseapp.com
    NEXT_PUBLIC_FIREBASE_PROJECT_ID=your-project-id
    NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=your-project-id.appspot.com
    NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=...
    NEXT_PUBLIC_FIREBASE_APP_ID=1:...:web:...

    # This is your Google AI API Key for Genkit
    GEMINI_API_KEY=AIza...
    ```

### 4. Running the Application

*   **Run the development server:**
    ```bash
    npm run dev
    ```
    Open [http://localhost:3000](http://localhost:3000) to see the app.

*   **Run the Genkit development server (in a separate terminal):**
    This allows you to inspect and test your AI flows.
    ```bash
    npm run genkit:watch
    ```
    Open [http://localhost:4000](http://localhost:4000) to see the Genkit developer UI.

## 🔄 Core Logic: The Claim Lifecycle

Traceback is built around a secure and logical state machine for handling claims.

1.  **Submission**: A user who lost an item finds a potential match and submits a claim.
2.  **Verification**: The user answers AI-generated questions about the item's physical appearance.
3.  **Review (`pending`)**: The person who *found* the item reviews the answers and **Approves** or **Rejects** the claim.
4.  **Approval (`approved`)**:
    *   Contact details are securely exchanged within the claim document.
    *   The user who *lost* the item is now prompted to generate a secure, one-time handover PIN.
5.  **PIN Generated**:
    *   The 6-digit PIN is shown once to the owner.
    *   The person who *found* the item now sees an input to verify the PIN.
6.  **Handover & Closure (`closed`)**: The two parties meet. The owner provides the PIN to the finder, who enters it into the app. On successful verification, the claim is marked as "closed", completing the process.

This entire flow is enforced by strict, field-level Firestore Security Rules to ensure users can only perform actions appropriate to their role.
