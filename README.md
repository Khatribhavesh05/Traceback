# Traceback: A Privacy-First Lost & Found Platform

Traceback is a modern, reliable, and privacy-conscious web application designed to help people reconnect with their lost belongings. Built with a powerful tech stack including Next.js, Firebase, and Google's Genkit, it offers a seamless experience for both reporting lost items and helping honest finders return them.

## ✨ Core Features

*   **✨ Intuitive Reporting**: Separate, streamlined forms for reporting **Lost Items** and **Found Items**, designed for quick and easy data entry, with optional image uploads to improve accuracy.

*   **🤖 Advanced AI Matching**: Our sophisticated AI analyzes item descriptions, categories, and optional images to calculate a precise match probability, connecting lost items with found reports far more effectively than traditional methods.

*   **🔐 Privacy-First Verification & Handover**: The entire claim process is engineered to protect user privacy until a match is confirmed and both parties agree to proceed.
    *   **AI-Generated Questions**: To prove ownership, claimants answer a series of unique, non-invasive questions generated by AI based on the item's physical characteristics. These questions are designed to be verifiable by the finder *without unlocking or interacting with the item*.
    *   **Secure PIN Handover**: Once a claim is approved, the owner generates a one-time, 6-digit PIN. This PIN is shared in person and verified by the finder in the app, confirming a secure handover without sharing contact info prematurely. It's like an Amazon OTP for your lost belongings.
    *   **Controlled Contact Exchange**: Only after a claim is approved are contact details securely exchanged between the two involved parties, directly within the claim view.

*   **👤 Centralized User Dashboard**: A personal command center where users can manage their reports, track the status of active claims, view AI-powered matches, and see a history of their resolved items.

*   **🚀 Built for Scale**: Leveraging a modern serverless stack with Next.js and Firebase (Firestore and Auth), Traceback is built to be fast, real-time, and highly scalable.

*   **💅 Sleek & Responsive UI**: A modern interface built with ShadCN UI and Tailwind CSS, providing a great experience on any device.

## 🚀 Tech Stack

*   **Framework**: [Next.js](https://nextjs.org/) (App Router)

## ⚙️ Getting Started

### 1. Prerequisites

*   Node.js (v18 or later)
*   A Firebase project.

### 2. Setup

1.  **Clone the repository:**
    ```bash
    git clone <your-repo-url>
    cd <repo-name>
    ```

2.  **Install dependencies:**
    ```bash
    npm install
    ```

3.  **Configure Environment Variables:**

    Create a `.env` file in the root of the project and add your Firebase project configuration. You can get these from your Firebase project settings.

    ```env
    NEXT_PUBLIC_FIREBASE_API_KEY=AIza...
    NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your-project-id.firebaseapp.com
    NEXT_PUBLIC_FIREBASE_PROJECT_ID=your-project-id
    NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=your-project-id.appspot.com
    NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=...
    NEXT_PUBLIC_FIREBASE_APP_ID=1:...:web:...

    # This is your Google AI API Key for Genkit
    GEMINI_API_KEY=AIza...
    ```

### 4. Running the Application

*   **Run the development server:**
    ```bash
    npm run dev
    ```
    Open [http://localhost:3000](http://localhost:3000) to see the app.

*   **Run the Genkit development server (in a separate terminal):**
    This allows you to inspect and test your AI flows.
    ```bash
    npm run genkit:watch
    ```
    Open [http://localhost:4000](http://localhost:4000) to see the Genkit developer UI.

## 🔄 Core Logic: The Claim Lifecycle

Traceback is built around a secure and logical state machine for handling claims. This entire flow is enforced by strict, field-level Firestore Security Rules to ensure users can only perform actions appropriate for their role and the current state of the claim.

1.  **Submission**: A user who lost an item finds a potential match and submits a claim by answering AI-generated verification questions.
2.  **Review (`pending`)**: The person who *found* the item reviews the claimant's answers and **Approves** or **Rejects** the claim.
3.  **Approval (`approved`)**:
    *   Contact details are securely exchanged within the claim document, visible only to the two parties.
    *   The user who *lost* the item is now prompted to generate a secure, one-time handover PIN.
4.  **PIN Generated**:
    *   The 6-digit PIN is shown *once* to the owner.
    *   The person who *found* the item now sees an input field to verify the PIN during the physical handover.
5.  **Handover & Closure (`closed`)**: The two parties meet. The owner provides the PIN to the finder, who enters it into the app. On successful verification, the claim is marked as "closed", completing the process and resolving the item.
